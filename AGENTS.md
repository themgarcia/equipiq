# AGENTS.md

- Category defaults live in the `category_defaults` table (with `category_consumables` as its child); the client array in `src/data/categoryDefaults.ts` stays as the reference for calculations until full cutover — why: the table is extensible and overridable, and the parity test (`scripts/seed/categoryDefaults.parity.test.ts`) must pass before anything else reads from it.
- Seed data for category tables is generated from the client array by `scripts/seed/generateCategorySeed.ts`, never hand-typed — why: values must match exactly.
- Annual recovery is computed only by `annualRecovery(item, basis)` in `src/lib/calculations.ts`, with the basis read from `company_settings` via `useCompanySettings` — why: Cashflow and FMS Export once diverged under the same label; one function keeps them identical.
- Company-wide settings live in `company_settings`, one row per user today, with a reserved nullable `org_id` — why: lets settings move to an organisation later by filling `org_id` instead of reshaping data.
- Per-unit operating costs (maintenance, insurance, licensing, fuel) resolve only through `resolveOperatingCosts` in `src/lib/operatingCosts.ts` and are display-only until the export step wires them in — why: one place decides override vs default vs "Not set" (null, never silently 0).
- The annual insurance premium lives on the equipment row (`insurance_annual_premium`) and is edited only from the Insurance page — why: insurance data stays in one place, not duplicated on the equipment form.
- Contractor edits to category defaults are stored per user in `user_category_overrides` and merged over the shared defaults in `EquipmentContext`; `category_defaults` stays admin-only — why: one company's edit must never change another company's defaults.
- Service divisions (`service_divisions`) are user-defined with no seeded or suggested names, and each unit's split lives in `equipment_division_allocations` (a row with a null division = year-round shared) — why: names must match the contractor's own LMN budgets.
- Division shares are a user judgment: `src/lib/divisionShares.ts` only suggests shares and describes the months total, and saves go through `replace_equipment_allocations` (invoker rights) so the deferred total-100% check sees the whole set at once — why: overlap can't be decided by a rule.
- Each allocation row carries recovery method (owned/leased) and `allocation_type`, the router that sends that share to the price list (operational) or that division's overhead budget (overhead_only/owner_perk); `rate_basis` and `equipment.lmn_recovery_method`/`allocation_type` are deprecated and trigger-synced until the export cutover — why: seasonal recovery is a budget-export route, not a rate basis, and the existing export keeps working unchanged.
- Effective division allocation resolves only through `resolveAllocation` in `src/lib/divisionAllocation.ts`: unit override (`is_override`), then `category_division_allocations`, then year-round shared — why: set the category once, override only the exceptions.
- Never render a component defined inside another component's body as `<Inner />`; call it as `{Inner()}` or lift it out, and hold numeric input as text until save — why: remounting on every keystroke dropped digits ("11" saved as "1").
